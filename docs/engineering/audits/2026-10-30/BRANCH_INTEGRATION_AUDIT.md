## Cobertura e método

API REST paginada: branches páginas 1/2 = 64/0; pulls state=all páginas 1/2 = 70/0. Os 70 HEADs foram buscados em refs/audit/pull/N, incluindo branches removidas. Fetch remoto com prune antes de comparar; a referência main acima foi conferida na API e no Git. Nenhuma limitação de 500 itens foi usada como garantia de cobertura. O snapshot precede as PRs produzidas por esta auditoria; essas recebem apêndice próprio.

Para cada branch: merge-base, contagem main-only/branch-only, log --left-right --cherry-pick, git cherry, diff merge-base..HEAD, árvore/blobs e paths ausentes. Merges exclusivos foram abertos para identificar destino e conteúdo dos pais; histórico não foi confundido com presença funcional. Testes atuais e checks históricos são evidências distintas. [BRANCH_CI_EVIDENCE.json](BRANCH_CI_EVIDENCE.json) registra todos os HEADs e checks retornados, sem afirmar que ausência de check significa ausência de execução.

Git não registra a branch original de criação; o destino real de cada PR e o merge-base são fatos verificáveis, enquanto origem anterior não documentada permanece desconhecida. Data do commit não equivale a atualização da ref no servidor. Não inventamos essas duas informações.
