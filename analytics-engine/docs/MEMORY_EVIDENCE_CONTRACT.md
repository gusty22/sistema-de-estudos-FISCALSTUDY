# Memory evidence contract

This module distinguishes observed repeated-item outcomes from an exploratory time association. FSRS remains the authority for item-memory scheduling. Neither a subject name, current-answer confidence nor one unexpected error establishes a forgetting curve or a conceptual diagnosis.

- `classify_attempt_history` matches catalog metadata without multiplying events or creating `.x`/`.y` columns. Existing observation metadata is preserved; missing values can be filled from the catalog. Identical catalog duplicates are idempotent; conflicting identity metadata is rejected. Exposure keys contain both discipline and topic. A new item in a topic is not proof of transfer.
- `fit_empirical_decay_model` fits correctness against log observed interval only. It requires sufficient repetitions and outcome/interval variation; convergence, rank, finite uncertainty and absence of numerical separation are checked. Missing or failed fits have `NA` coefficients, never default priors. Current-answer confidence is excluded to avoid information leakage. Slopes are not clipped to fit a desired theory. `EXPLORATORY_FIT` is an in-sample association, not a validated personal memory model. Repeated events are dependent, and temporal holdout calibration is still required.
- Per-discipline fits use the same checks. No rate is assigned from the discipline name. No half-life is imputed. Observed accuracy remains descriptive.
- `project_critical_intervention_point` retains a compatibility envelope with observed counts/accuracy and its Wilson interval, but reports `FSRS_REQUIRED` and `UNVALIDATED_MODEL`; it emits no future deadline, prediction-based Wilson interval or executable curve. Missing counts remain missing.
- `calculate_robin_hood_weights` retains the existing Java JSON shape while returning empty weights, zero disciplines and `can_apply=false`. No elapsed days, available minutes, time donor, emergency intervention or confidence penalty is invented. The backend keeps its configured plan and validated FSRS schedule. The Java DTO supports unknown additive metadata and empty maps, but this R-only change does not constitute executed Java integration testing.

The old tests that expected a negative slope from three observations or a slower forgetting rate for Constitutional Law than Auditing were removed because those assertions enforced fabricated evidence. Replacement regressions cover insufficiency, positive observed slope, current-confidence invariance, singular/separated fits, subject-name invariance, zero denominators, catalog cardinality and topic boundaries. Validation results are recorded by the central QA owner after the combined R suite runs.

Exposure labels use `exposure_basis=RECORDED_ATTEMPTS_ONLY`. INITIAL_EXPOSURE means the first attempt in the available event history; it does not prove that the student never saw the item or concept before. The 24-hour category boundary is an operational heuristic, not proof of recognition versus retrieval as a cognitive mechanism.

Focused validation: R 4.5.1, LC_ALL=C and LANG=C, actual descriptive/profile dependencies plus tests/test_retention.R: 45 checks passed, exit 0. Log: r-memory-focused.log (local). Parsing and git diff --check passed. This focused harness is not the combined suite, executed Java integration or proof of learning efficacy.

## Comparação entre recuperação prevista e resultado observado

Quando a exportação fornecer `fsrs_retrievability_pre_update`, `fsrs_prediction_timestamp`, `fsrs_model_version` e `fsrs_evidence_status`, `calculate_retrieval_surprise()` compara o estado de memória FSRS anterior à atualização com o resultado da tentativa. Uma resposta errada sob baixa recuperação prevista é compatível com esquecimento esperado; um erro sob alta recuperação prevista vira apenas candidato a investigação com o estudante. Nenhum desses padrões identifica sozinho a causa.

A previsão é capturada durante o envio da resposta, a partir do estado FSRS antes de processar o novo resultado. Ela não é uma medição registrada antes da primeira exposição à questão. Registros sem timestamp anterior ao evento, versão conhecida ou estado elegível são excluídos. `COLD_START` não é probabilidade. Brier e log-loss são descrições por versão do modelo e não demonstram calibração individual. Os limites baixo/alto são faixas de triagem configuráveis e ainda não validadas. Essa análise não altera o FSRS, agenda revisão, estima domínio conceitual nem escolhe intervenção.
